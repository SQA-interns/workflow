# End-to-end scenarios

> Owner: Product owner · Read in: phases 3, 6 · Agent: read-only

The end-to-end tests of this project: exactly one test per scenario below, run against the real local stack (`docker compose up`: frontend, backend, PostgreSQL, Firebase Auth Emulator) through the browser, and the same in every run of this project. Users are created and their emails verified through the emulator's REST API (`project/02_design/api-contract.md`, "Local stack"); everything else happens in the browser. The agent writes no other end-to-end test and no scenario is merged or split. Each scenario names the criteria it demonstrates; the acceptance tests (one or more per criterion) carry the detailed cases, so an end-to-end test checks the journey once and does not repeat them. Every scenario also runs the accessibility check of NFR-06 on each main page it visits (Workspace list, Contact list, Contact page, history page, Duplicates page).

| ID | Scenario | Steps and observations | Covers |
|---|---|---|---|
| E2E-01 | First Contact in a new Workspace | Sign up with email and password, sign in, create the Workspace `Konferenca 2026`, add a Contact with every Predefined field, the Attributes `kompetenca=spletnoProgramiranje` and `jezik=nemščina` and the Tags `udelezenec2025` and `neObvescaj`. The Contact appears in the list with its Tags; its page shows every value; the Tag list shows both Tags with count 1. Sign out: the sign-in page is shown. | AC-001-04, AC-002-01, AC-005-01, AC-006-01, AC-007-01, DoD-P01 |
| E2E-02 | Find and export | In a Workspace with 6 Contacts, search, filter by a Tag and an Attribute: only the matching Contacts and their count are shown. Select 2 of them and export: the downloaded workbook has the header row and exactly those 2 rows with their Tags and Attribute columns. Clear the selection and export the filter: the workbook has exactly the matching Contacts. | AC-008-08, AC-012-01, AC-012-02, AC-012-03, AC-012-06, DoD-P03 |
| E2E-03 | Isolation | User A creates a Workspace with a Contact. User B signs in: A's Workspace is not in B's list; opening A's Workspace URL and A's Contact URL shows "not found" and none of A's data; B's own search for the Contact's name finds nothing. | AC-004-01, AC-004-04, AC-002-03, DoD-P02 |
| E2E-04 | History and Restore | Edit a Contact twice (change the email, then remove a Tag). The history page shows Revisions 3, 2, 1 with author, time and the changed values. Restore Revision 1: the Contact shows the original email and Tag, and the history shows Revision 4 of type Restore. Delete the Contact: it disappears from the list and appears in the Deleted view; restore it from there: it is back in the list. | AC-009-02, AC-009-04, AC-009-06, AC-009-07, AC-005-07, AC-008-07 |
| E2E-05 | Duplicate warning and Merge | Create a Contact, then a second one with the same email in other letter case and another phone: a warning names the first Contact with a link, and the second stays saved. The Duplicates page lists both as one set. Merge them, keeping the first as Survivor and the second's phone: the Survivor shows the chosen phone and the Tags of both; the set is gone; the other Contact is in the Deleted view. | AC-010-06, AC-010-07, AC-011-01, AC-011-02, AC-011-07, AC-011-04 |
| E2E-06 | Viewer invited before sign-up | The Owner adds a not-yet-registered email as Viewer: it is listed as a pending invitation. That person signs up, verifies the email and signs in: the Workspace is in their list with Role Viewer; they can search and export, and no create, edit, delete, restore, merge or Tag controls are shown. A direct update request with their token is refused (HTTP 403). | AC-003-02, AC-005-08, AC-009-07, AC-012-07, DoD-P02 |
| E2E-07 | Slovenian characters survive the whole chain | Create a Contact `Saša Šuštar-Žorž`, company `Čebelarstvo Ćirić d.o.o.`, Attribute value `čebelarjenje`. Searching `sasa` and `zorz` finds it; the Contact page, the database row and the exported workbook hold the text unchanged. | AC-005-05, AC-008-01, AC-012-04, NFR-01 |
| E2E-08 | Export and import into another Workspace | In a Workspace with 3 Contacts (Tags, Attributes, Slovenian characters), export all of them. Create a second Workspace and import the downloaded workbook from its Contact list: the page reports 3 created Contacts and lists them with the same values and Tags. Import a workbook with one invalid email: the error names its row, and the list is unchanged. | AC-014-02, AC-014-05, AC-014-13, DoD-P07 |

Not end-to-end tests (verified by runtime demonstration in phase 6): NFR-02 (data survives recreation of every container), NFR-04 (health and readiness) and NFR-07 (response time with 10,000 Contacts).
